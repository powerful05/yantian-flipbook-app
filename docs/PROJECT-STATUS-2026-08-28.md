# 盐田 Flipbook 项目进度与分阶段实施清单

> 更新时间：2026-08-30  
> 本次 MVP 验证地址：`http://127.0.0.1:4190/?demo=mvp`  
> 仓库默认模式：Mock；本机 `.env.local` 当前显式开启百炼适配器（本次未提交生成请求）

## 先说结论

项目已经从“架构方案”进入“可运行的 P2 原型，并完成 P3 的本地动效与云端适配器切片”。本轮又把 7 张用户参考图归档并接入 Qwen-Image I2I 请求，但还没有达到 Flipbook 官方演示的动态效果。当前已经能验证的是：画布、节点图、SSE 状态流、热点解释、子节点生成、历史返回、本地微动、视频层合成、视频失败降级、进程内动效缓存和风格参考输入顺序。尚未验证的是：真实百炼样本质量、可复用的持久化节点、视频视觉连续性、预取预算和真流式增量推理。

“百分之百复刻官方”不是可验证的工程承诺。官方后端、模型版本、队列和缓存策略不可见，公开演示视频也标注为预生成并为速度剪辑。项目采用可测的替代口径：视觉连续性、点击定位、已知节点跳转延迟、草稿/最终图延迟、视频可播放率和失败降级率。

本次新增的 `WorldRuntime` MVP 已完成本地实现并通过浏览器验收：固定 5 场景、15 个实体、两级下钻、返回、吊具小车本地状态、`sessionStorage` 恢复和 320/390 px 布局均可用。它是固定本地 2.5D 世界，不是完整 3D、真流式视频或持久化生产世界。

## 逐步实施顺序

### Step 1：冻结 P0/P2 合同和验收基线

当前已完成代码验证，下一次评审要冻结：

- `GenerationRequest`、`GenerationEvent`、`SceneNode` 的版本和错误码。
- 20 场景标注中每个锚点的 point/bbox、标签和来源状态。
- 桌面、390 px、320 px 三个视口的截图和交互记录。

验收：合同测试、数据集校验、浏览器冒烟全部绿色。

### Step 2：用小样本验证百炼静态链路

参考包和提示词编译已经先落地；真实付费样本仍要单独确认权限、价格和样本上限后再做。执行时只在服务端配置轮换后的 Key，并显式打开 `MODEL_REQUESTS_ENABLED`。先做：

1. 一张根页面。
2. 一次父图点击解析。
3. 一次基于父图和点击区域的子图编辑。

适配器已经支持 Qwen 文本/VL、Qwen-Image 异步任务、最多 3 张风格参考图和模型收据；还需要记录真实耗时、资源 URL 时效、模型返回 JSON 稳定性、中文文字和连续性评分。付费调用前单独确认模型权限和费用上限。

### Step 3：接入持久化和已知边零生成跳转

- MongoDB 保存 Session、SceneNode、Edge、Anchor、ModelReceipt。
- OSS/MinIO 保存图片和视频，并在临时 URL 过期前转存。
- 分享 URL 只 hydrate 已有节点，不重新生成。
- `session + parent + anchor + prompt_hash + model_profile` 作为幂等键。

验收：刷新或分享打开已有节点不产生模型请求；重复点击不产生重复节点或重复扣费。

### Step 4：完成 P3 动效增强

- 点击后立即执行本地确定性缩放/平移，目标点和最终图片裁剪窗口一致。
- 静态图完成后异步提交 `wan2.2-kf2v-flash` 到 `/api/v1/services/aigc/image2video/video-synthesis`，只在首帧和尾帧都确定时使用。
- 停留动效使用 `wan2.6-i2v-flash` 到 `/api/v1/services/aigc/video-generation/video-synthesis`，不承担页面跳转落点。
- 视频资源按首帧 SHA、尾帧 SHA、动作 profile、模型版本和 seed 缓存。
- 视频失败、超时或预算不足时保留静态图和本地过渡。

当前离线验收：视频请求不会阻塞最终图；Mock 视频可解码并与 Canvas 合成；缓存命中不重复请求；任务失败和取消会回退到静态图。真实百炼样本、持久化缓存和视觉质量阈值仍待完成。

### Step 5：实现预取、取消和预算

- 每页最多预取 3 个高置信锚点，默认只预取静态图。
- 新点击优先级高于视频增强和低优先级预取。
- 请求级 `AbortController` 已接入；供应商任务取消、每日预算和审计记录仍待补齐。
- 预算达到阈值后自动降级为本地过渡，不再提交新付费任务。

验收：取消请求后不会继续提交后续付费阶段；预算和重试次数可审计。

### Step 6：单独评估真流式

托管异步视频接口不能直接证明真流式。若要达到真正低首帧延迟，需要独立 GPU worker：增量推理、fMP4 init/media segment、WebSocket sequence、背压、Origin 校验、鉴权、恢复和冷启动指标都要分别实现和测量。

验收：没有暖实例数据前，不对外宣称“实时视频生成”。

### Step 7：上线质量和回滚

- 增加鉴权、上传限制、内容安全、审计日志和敏感信息扫描。
- 进行 100 次连续点击、并发、断线、重复幂等和刷新分享压测。
- Web、编排器、图片 worker、视频 worker 分开扩缩；数据服务不直接暴露公网。
- 保留 Mock 降级和旧静态资源，模型或视频故障时可回滚。

## 模型和密钥边界

- 项目只读取服务端 `DASHSCOPE_API_KEY`，浏览器永远不接收 Key。
- `.env.example` 只保留空占位符；本地推荐运行 `npm run dev:models` 在隐藏输入中提供 Key。
- `MODEL_REQUESTS_ENABLED=false` 是默认安全状态。
- 当前适配器的 `cost_cny: 0` 仅表示尚未接入实时计费计量，不代表真实调用免费；上线前必须接入价格/账单记录。

## 当前明确缺口

1. 风格参考包已接入，但没有真实百炼生成样本和质量基线，无法确认风格/文字/连续性达标。
2. 节点和资源仍是进程内内存，重启后丢失。
3. 分享 URL 目前只展示快照参数，不能从服务端恢复节点。
4. 视频资源字段、异步任务轮询、失败降级和进程内缓存已完成；仍缺 OSS/MinIO 持久化、跨进程缓存和供应商任务取消。
5. 没有候选预取、并发锁、鉴权、用户/会话/日预算。
6. 没有 OCR、引用检索和自动质量评分闭环。
7. 没有真流式 GPU worker，不能承诺模型生成的首帧实时到达。
8. 官方公开 live 画布约为 16:9，当前项目图片/坐标合同为 16:10；尚未做比例迁移和回归。
