# 即时过渡与锚点连续性加固

## 范围

修复点击生成图内“海洋世界”等目标时可能被重新识别为“小梅沙”的路径，并让首次点击在云端生成完成前就显示确定性的本地聚焦过渡。本次没有发起新的百炼付费请求。

## 修改文件

- `src/flipbook-engine.mjs`
  - tap 请求优先使用父节点中明确的 `anchor_id`；ID 不属于父节点时返回稳定错误，不再接受供应商返回的其他地点。
  - 对缺少 ID 的 tap 请求按查询文本和归一化坐标复用已知锚点。
  - 子节点保留目标锚点作为首个锚点，避免下一层再次丢失目标。
- `src/bailian-scene-pipeline.mjs`
  - 重复标签按点击点选择最近候选；已知候选不再无条件回退到 VLM。
- `client/anchor-hit-testing.mjs`
  - 新增可测试的本地锚点命中函数；兼容生成节点的 `point` 和画布旧数据的 `x/y`，在 bbox 不明确时用查询文本消歧，再选择最近锚点。
- `app.js`
  - 生成图的热点命中区按 bbox 扩大。
  - 点击后立即更新目标查询上下文和本地聚焦状态。
  - tap 期间保留父图聚焦，不提前展示未经连续性确认的 draft。
  - 子节点缓存同时按服务端和客户端锚点 ID 建索引。
- `index.html` / `styles.css`
  - 增加 `FOCUS / LOCAL` 目标提示；过渡变换使用锚点中心和轻量模糊。
- `tests/anchor-hit-testing.test.mjs`、`tests/flipbook-engine.test.mjs`、`tests/bailian-scene-pipeline.test.mjs`
  - 覆盖错误供应商锚点、重复标签偏移点击和本地命中行为。

## 行为变化

之前：点击内嵌文字或建筑边缘可能没有稳定 `anchor_id`，请求再次调用视觉模型，结果可能变成无关地点；首次点击要等生成事件才有明显反馈。

现在：浏览器先按已知锚点完成本地缩放/平移，搜索栏和目标提示立即切换；后端收到明确 ID 时锁定目标，云端 draft 不会在 tap 过程中覆盖父图。

## 部署与回滚

重启 `node --env-file-if-exists=.env.local server.mjs` 后刷新页面即可加载。回滚时只需恢复上述代码文件；本次没有修改数据库、对象存储或用户数据。

## 边界

云端图像模型最终生成的像素仍需真实样本评测；本次保证的是导航目标和等待期间的即时反馈，不把本地过渡宣传为真流式视频。
